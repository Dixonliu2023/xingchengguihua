# 融合逻辑说明

## 概述

本文档说明如何将Product Designer（产品设计）与Multi-Agent（自动化执行）两个系统的输出进行融合。

## 融合层级

### Level 1: 数据层融合

**来源：**
- Product Designer: 产品定位、资源解构、体验设计
- Multi-Agent: 需求解析、景点筛选、路径验证
- 飞书知识库: 特别玩法、风险预警

**融合方式：**
```
输入数据 = Product Designer(定位+解构) + Multi-Agent(解析+验证) + 飞书(玩法+预警)
```

---

### Level 2: 文档层融合

#### 简易行程表

| 数据来源 | 内容 |
|---------|------|
| Agent 3 | 每日时间安排、交通衔接 |
| 飞书玩法 | ⭐标记的特别体验 |
| Product Designer | 峰终设计、氛围安排 |

**融合规则：**
1. Agent 3输出作为基础框架
2. 飞书玩法插入对应时段（⭐标记）
3. Product Designer内容作为补充说明

---

#### 销售推介文档

| 数据来源 | 内容 |
|---------|------|
| Product Designer | 卖点提炼、价值主张、差异化 |
| Agent 3 | 行程亮点、销售话术 |
| 飞书玩法 | 独家体验、情绪价值 |

**融合规则：**
1. Product Designer Module E（商业策略）作为核心框架
2. Agent 3的行程亮点填充细节
3. 飞书玩法的情绪价值作为"独家体验"突出展示

---

#### 产品文档（完整版）

| 数据来源 | 内容 |
|---------|------|
| Product Designer | 6个模块完整内容 |
| Agent 2 | 验证结果（通达性、风险） |
| 飞书知识库 | 目的地元素、资源解构 |

**融合规则：**
1. Product Designer 6模块作为主体结构
2. Agent 2验证结果作为附件
3. 飞书元素作为资源解构的补充

---

#### PRD文档

| 数据来源 | 内容 |
|---------|------|
| Product Designer | 产品背景、需求分析、体验设计 |
| Agent 3 | 运营策略、成本分析 |
| Agent 2 | 风险评估 |

**融合规则：**
1. Product Designer PRD模板作为框架
2. Agent 3成本分析填入第6章
3. Agent 2风险预警填入第7章

### Level 3: 流程层融合

#### 快速生成流程

```
Product Designer(简化版) 
    ↓
    ├─→ Module A: 产品定位（简化）
    │       ↓
    │   飞书检索：目的地信息
    ↓
    ├─→ Module B: 资源解构（简化）
    │       ↓
    │   飞书检索：元素挖掘
    ↓
Multi-Agent
    ↓
    ├─→ Agent 1: 需求解析+飞书同步检索
    │       ↓
    │   输出：融合候选清单
    ↓
    ├─→ Agent 2: 路径验证+风险预警
    │       ↓
    │   输出：验证结果
    ↓
    └─→ Agent 3: 行程规划+文档生成
            ↓
            输出：简易行程表+销售推介
```

#### 深度设计流程

```
Product Designer(完整版)
    ↓
    ├─→ Module A: 产品定位
    │       ↓ 交互确认
    │   飞书检索：目的地背景
    ↓
    ├─→ Module B: 资源解构
    │       ↓ 交互确认
    │   飞书检索：元素挖掘+特别玩法
    ↓
    ├─→ Module C: 行程设计
    │       ↓ 交互确认
    │   高德验证：通达性+路径优化
    ↓
    ├─→ Module D: 氛围仪式
    │       ↓ 交互确认
    ↓
    ├─→ Module E: 商业策略
    │       ↓ 交互确认
    ↓
    ├─→ Module F: 风险应对
    │       ↓ 交互确认
    │   飞书检索：风险预警
    ↓
Multi-Agent
    ↓
    ├─→ Agent 2: 路径优化（增强验证）
    ├─→ Agent 3: 文档生成（完整版）
    └─→ 输出：产品文档+PRD+简易行程表+销售推介
    
知识库回写（可选）
    ↓
    识别新亮点 → 去重检查 → 回写入库
```

## 数据映射

### 需求输入 → 路由判断

```
用户输入
    ↓
需求结构化 {destination, days, participants, theme, budget, timeline, customer_type}
    ↓
路由评分 = f(目的地热度, 需求复杂度, 客户类型, 时间要求)
    ↓
工作流选择：快速生成 / 深度设计
```

### 产品定位 → 飞书检索

```
Product Designer Module A 输出
    ↓
产品定位 {目标人群, 产品层次, 价值主张}
    ↓
飞书检索参数构建
    {
        city: destination,
        categories: [theme对应的分类],
        suitable_for: [目标人群],
        emotional_value: [价值主张对应的情绪]
    }
    ↓
飞书输出：目的地信息 + 特别玩法列表
```

### 验证结果 → 文档生成

```
Agent 2 验证输出
    {
        reachable_pois: [...],
        risk_warnings: [...],
        daily_combination: [...]
    }
    ↓
文档生成器
    ├─→ 简易行程表：直接嵌入验证后的POI
    ├─→ 销售推介：标注⭐飞书玩法+风险提示
    ├─→ 产品文档：验证结果作为附件
    └─→ PRD：风险评估填入对应章节
```

## 冲突处理

### 冲突类型与解决方案

| 冲突类型 | 描述 | 解决方案 |
|---------|------|---------|
| 飞书玩法与验证冲突 | 飞书推荐的玩法在路径验证中显示不可达 | 保留玩法，提供替代方案或调整顺序 |
| 多飞书玩法时间冲突 | 同一天安排了多个飞书玩法时间冲突 | 按优先级保留，调整到其他日期 |
| 飞书玩法与预算冲突 | 飞书玩法价格超出预算 | 提供降级选项或移除 |
| Product Designer与Agent冲突 | Product Designer的体验设计与Agent验证冲突 | 以验证结果为准，Product Designer内容调整为备选 |
