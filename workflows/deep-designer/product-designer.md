# 深度设计工作流 - Product Designer完整流程

## 概述

本文档定义深度设计流程，整合Product Designer（产品设计）与飞书知识库，完成高价值产品的全流程设计。

## 工作流程

```
用户输入
    ↓
智能路由判断 → 深度设计
    ↓
模块A：产品定位 ← 飞书：目的地信息
    ↓ 交互确认
模块B：资源解构 ← 飞书：元素挖掘+玩法
    ↓ 交互确认
模块C：行程设计 ← 高德：路径验证
    ↓ 交互确认
模块D：氛围仪式
    ↓ 交互确认
模块E：商业策略
    ↓ 交互确认
模块F：风险应对 ← 飞书：风险预警
    ↓ 交互确认
文档生成 ← Product Designer输出 + Agent2验证 + 飞书玩法
知识库回写 ← 识别新亮点
```

---

## 模块A：产品定位

### 输入
- 用户需求（目的地、天数、人群、主题）
- 飞书目的地信息

### 操作
1. 解析目的地信息
2. 确定产品层次（路线/产品/作品）
3. 定义目标消费者画像
4. 提炼产品价值主张

### 输出
- 产品定位文档
- 目标消费者画像
- 产品价值公式

### 交互确认
```
📋 【节点1-产品定位确认】
已完成：
- 产品名称：{产品名称}
- 目标人群：{人群描述}
- 产品层次：{路线/产品/作品}
- 价值主张：{功能+情绪+资产价值}

请回复"确认"继续，或提出修改意见：
```

---

## 模块B：资源解构

### 输入
- 产品定位
- 飞书目的地元素

### 操作
1. 获取目的地元素（游牧/农耕/商贸/手工艺/宗教/历史）
2. 识别隐性之美
3. 设计任务化体验
4. 同步检索飞书特别玩法

### 输出
- 目的地元素清单
- 隐性之美描述
- 任务化体验设计表

### 交互确认
```
📋 【节点2-资源解构确认】
已完成：
- 核心元素：{元素列表}
- 隐性之美：{隐性之美描述}
- 任务化体验：{任务列表}
- 飞书玩法：{玩法列表}

请回复"确认"继续，或提出修改意见：
```

---

## 模块C：行程设计

### 输入
- 资源解构结果
- 高德路径验证

### 操作
1. 设计每日行程框架
2. 调用高德MCP验证通达性
3. 执行"不走回头路"检查
4. 设计峰终体验

### 输出
- 每日行程安排
- 峰终设计
- 哇点清单

### 交互确认
```
📋 【节点3-行程设计确认】
已完成：
- Day1：{主题} → {活动}
- Day2：{主题} → {活动}
- ...
- 峰终设计：{峰值体验} + {终点体验}

请回复"确认"继续，或提出修改意见：
```

---

## 模块D：氛围仪式

### 输入
- 行程设计
- 客户类型

### 操作
1. 设计氛围四部曲
2. 破冰环节设计
3. 合影记忆点设计
4. 分享总结设计

### 输出
- 氛围四部曲安排
- 破冰环节
- 合影场景

### 交互确认
```
📋 【节点4-氛围仪式确认】
已完成：
- 破冰环节：{方式}
- 仪式设计：{仪式}
- 合影记忆点：{场景}
- 分享总结：{方式}

请回复"确认"继续，或提出修改意见：
```

---

## 模块E：商业策略

### 输入
- 产品定位
- 行程设计

### 操作
1. 提炼卖点（购买理由）
2. 提炼亮点（超出预期）
3. 定价策略
4. 品牌价值

### 输出
- 卖点清单
- 亮点清单
- 定价建议

### 交互确认
```
📋 【节点5-商业策略确认】
已完成：
- 核心卖点：{卖点列表}
- 产品亮点：{亮点列表}
- 建议售价：{价格}
- 毛利率：{毛利率}%

请回复"确认"继续，或提出修改意见：
```

---

## 模块F：风险应对

### 输入
- 行程设计
- 飞书风险预警

### 操作
1. 识别潜在风险
2. 获取飞书风险预警
3. 设计应对预案
4. 确定保险方案

### 输出
- 风险清单
- 应对预案
- 保险覆盖

### 交互确认
```
📋 【节点6-风险应对确认】
已完成：
- 风险识别：{风险列表}
- 应对预案：{预案列表}
- 保险覆盖：{保险方案}

请回复"确认"继续，或提出修改意见：
```

## 文档生成

### 输出文档

| 文档 | 内容 |
|------|------|
| 产品文档 | Product Designer 6模块完整内容 |
| PRD文档 | 产品需求文档 |
| 简易行程表 | 每日行程+费用 |
| 销售推介 | 卖点+话术+价格 |

### 知识库回写

识别条件：
1. 标注为"新亮点"的内容
2. 飞书玩法库中不存在的玩法

回写流程：
1. 调用 write_back_to_feishu
2. 执行去重检查
3. 设置验证状态为"待验证"
